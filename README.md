# 家庭光伏储能调度 Web 应用

本机部署的家庭光储调度工具：填写未来 **96 个连续 15 分钟时段**（24 小时）的
用电、光伏预测、购电上限与分时电价，设置电池参数后，自动求解满足全部用电、
**不向电网送电**前提下购电费用最低的调度计划；执行过程中按顺序登记实测数据，
已执行时段锁定，后续计划按实测期末电量自动重算，旧计划随时可查。

- 后端：Python 3.11 + Flask + SQLite
- 求解：SciPy `linprog`（HiGHS）分层线性规划
- 前端：服务端渲染页面 + 原生 JS，无外部 CDN 依赖（可完全离线运行）

---

## 一、启动（Docker，一键）

需要本机已安装 Docker（含 Compose 插件）。

```bash
docker compose up -d --build
```

首次启动会自动：

1. 安装 Python 依赖（Flask、SciPy、gunicorn）；
2. 在宿主机 `./data/ems.db` 初始化 SQLite 数据库（幂等，重复启动不丢数据）；
3. 在容器内启动 gunicorn Web 服务。

访问地址：

| 页面 | 地址 |
| --- | --- |
| 调度总览（曲线/汇总/版本入口） | <http://localhost:8000/> |
| 96 段预测输入 | <http://localhost:8000/input> |
| 实测登记 | <http://localhost:8000/actuals> |
| 计划版本列表 | <http://localhost:8000/plans> |

停止与查看日志：

```bash
docker compose down          # 停止
docker compose logs -f       # 查看日志
```

数据保存在宿主机 `./data/ems.db`，删除容器不会丢失；
如需彻底重来：停止容器后删除 `./data` 目录，或在总览页点"清空数据"。

> 端口被占用时，编辑 `docker-compose.yml` 中 `"8000:8000"`，
> 左侧改为其它宿主机端口，例如 `"8080:8000"`，然后访问 <http://localhost:8080>。

## 二、不用 Docker 的本地启动

```bash
pip install -r requirements.txt
# 可选：自定义数据库位置（默认 /data/ems.db，容器外用请务必显式指定）
export DATABASE_PATH=./ems.db
python -m app.wsgi           # 开发服务器，默认 0.0.0.0:8000
# 生产方式：
gunicorn "app.wsgi:app" --bind 0.0.0.0:8000 --workers 2 --threads 4
```

访问 <http://localhost:8000/>。

## 四、使用流程

1. **填写预测**：打开"预测输入"，可点"填入示例数据"一键生成典型家庭曲线，
   核对/修改 96 段数据与电池参数后点"生成调度计划"。
2. **查看结果**：逐段购电、充电、放电、弃光、期末电量与费用；总览页有曲线与汇总。
3. **登记实测**：每个 15 分钟时段结束后，在"实测登记"页按顺序填写
   实际用电、实际光伏、实际购电与实测期末电量。
   - 系统校验能量平衡（不向电网送电）、购电上限、期末电量边界、每段充/放电上限；
   - 任一项不通过都会明确提示原因，**错误记录不会入库**，可修正后重新提交。
4. **锁定与重算**：提交成功的时段立即锁定不可修改；系统以实测期末电量为初值，
   对全部剩余时段重新求解最优计划，原计划保留为历史版本（只读可查）。
5. 若实测导致后续已无法满足全部用电，当前实测仍保存，页面会给出
   **余段最早供电缺口时段与缺口 Wh** 的警告；旧计划不受影响。

## 五、调度模型

每个时段（15 分钟，能量单位 Wh）的决策量：购电 `g`、充电 `c`、放电 `d`、弃光 `u`。

```
能量守恒（必须满足全部用电，不向电网送电）：
    用电 = 光伏 + 购电 + 放电 − 充电 − 弃光

0 ≤ 购电 ≤ 购电上限，0 ≤ 充电 ≤ 充电上限，0 ≤ 放电 ≤ 放电上限
保留电量 ≤ 期末电量 ≤ 容量，且电池每段不同时充放
期末电量 = 段初电量 + 充电 − 放电
```

分层优化目标：

1. 购电总费用 `Σ 购电(Wh) × 单价(元/kWh) / 1000` **最小**；
2. 费用相同时，充放电总量 `Σ(充电 + 放电)` **最小**（减少无谓循环）。

约束矩阵为网络流全幺模结构，整数输入下输出均为整数 Wh。
可行性由逐段贪心预检查判定，不可行时报告**最早**出现供电缺口的时段及缺口量，
并且**不保存计划**。

## 六、目录结构

```
.
├── Dockerfile
├── docker-compose.yml
├── docker-entrypoint.sh
├── requirements.txt
├── app/
│   ├── optimizer.py      # LP 建模、分层求解、缺口定位
│   ├── validation.py     # 输入与实测校验
│   ├── db.py             # SQLite 初始化与访问
│   ├── service.py        # 建计划 / 实测冻结 / 余段重算
│   ├── web.py            # Flask 路由与 JSON API
│   ├── sample_data.py    # 一键填充的示例曲线
│   ├── wsgi.py           # 启动入口
│   ├── templates/        # 总览/输入/实测/计划/版本 页面
│   └── static/           # 样式与公共 JS（含 SVG 曲线图）
└── tests/                # 优化器与端到端 API 测试
```
